## 数据表（state/）

`persons / items / factions / places / lines / locked / ledger / current` 八表 + `timeline / synopsis / relations / debts / milestones` 扩展表 + `sync_log.json`（章节同步指纹，幂等判定依据）+ `history/ch_XXX.json`（每章全息快照切片）+ `indices/`（co_occurrence、entity_timeline）+ `log/review/reconcile_vol_XX.md`（卷末对账存档）。

写入路径全部经 `_save_json` 原子替换；读取损坏时隔离为 `*.corrupt-<时间戳>` 并抛 RuntimeError（CLI 退出码 4）。

## 固定替换词表（lexicon · Stage 5 确定性替换）

**是什么**：一类用词错误是**无条件确定**的——无论什么语境，「钢针」在该书都该是「银针」、
「猪肝色」都该是「青紫色」。这类修正是**作者事先定好的死规则**，不需要 LLM 逐章判断。

**为什么放进引擎而不是 Auditor**：若交给 Auditor 每章手抄，**漏抄即静默失效**——
那正是本引擎最忌讳的失败模式（"修了个寂寞"）。放进引擎则一次定义、每章强制执行、永不遗漏。

**为何不违反不变量 8「引擎不做文学判断」**：词表**不是引擎的审美裁决**，而是**作者逐字给定的
映射表**。引擎只做字符串搬运，不新增、不推断、不评分——判断权 100% 留在作者手里。

**文件与优先级**（低 → 高，后者覆盖前者）：

| 层级 | 路径 | 用途 |
|---|---|---|
| 全局基线 | `templates/lexicon.json` | 跨书通用死规则 + Gemini 模型固有毛病，所有书共享 |
| 本书覆盖 | `<workspace>/lexicon.json` | 本书/本题材专有规则，可覆盖或停用基线条目 |

- **停用基线条目**：把值写成与原词相同（如 `"猪肝色": "猪肝色"`），即恒等映射 → 该条不生效；
  **逐键生效**——停用「瞬间」不会连带停用「的瞬间」（它们是彼此独立的规则）；
- **删除本书文件**只是"本书无额外规则"，**基线照常生效**（基线是全局资产，不被单本书连带取消）；
- **文件缺失是合法状态**（功能未启用）；但**存在而损坏必须硬阻断**（exit 1），绝不静默跳过；
- **`init` 只播种空骨架**，刻意不复制基线内容——否则本书旧副本会静默盖住日后的基线更新。

**三个段**：

| 段 | 值类型 | 语义 |
|---|---|---|
| `lexicon` | 字符串 | 定值替换；**空字符串 = 删除**；与原词相同 = 停用 |
| `rotate` | 字符串列表 | **轮换**：同一词按出现次序依次取不同候选，用于制造多样性 |
| `protect` | 字符串列表 | **保护**：这些固定词组整体豁免，绝不改动其中任何字 |

**执行语义**（`ops.py` `_load_lexicon` / `_apply_lexicon`）：

1. **长词优先**：原词按长度降序排列，保证「钢针盒」先于「钢针」、「的瞬间」先于「瞬间」命中。
   这条机制是安全删除「瞬间」的前提——「话音落下的瞬间」被更长的规则先接走变成「…落下时」，
   剩下的裸「瞬间」才被删除（实测：无此保护会留下 4 处「话音落下的，」残句）；
2. **保护词优先**：删除类规则有个**物理盲区**——待删词可能只是更长固定词的一部分
   （「安安静静」含「静静」、「年纪轻轻」含「轻轻」）。删掉会留下「安安」「年纪」。
   此类问题**无法用通用规则自动识别**（"安"与"坐"左右邻毫无规律），只能由作者在 `protect`
   显式声明豁免。保护词比所有规则都长，故在正则分支中天然优先；
3. **单遍不链式**：`re.sub` 不重扫刚插入的文本——即使表里同时有「钢针→银针」和「银针→金针」，
   钢针也只会变成银针。结果可预测、可安全重复执行（**幂等**）；
4. **在配方之后执行**：词表是最后一道确定性闸门，防止 LLM 把禁用词又写回 `ReplacementContent`
   （本项目 ch_003 实际发生过「刺鼻」被配方抄回正文的事故）；
5. **计数完全分离**：词表命中不污染配方回执的 `X/Y 应用`，否则 `recipe_zero_warning` 判断失真。

**轮换为何必要（实测数据）**：静态 1:1 替换**无法制造多样性**——把「瞬间」33 处统一换成「立刻」，
只是让「立刻」从 2 次涨到 35 次，**把瘾转移给了另一个词**。真正的多样性必须让同一个词
在不同位置得到不同处理。轮换起点由 `md5(章号 + 原词)` 决定：

- **同章重跑结果完全一致**（幂等 / 可复现，作者能重跑出昨天的稿子）；
- **不同章起点错开**，避免"横向的章内重复"变成"纵向的跨章重复"。

**回执语义**：`finalize` 每次都从 `raw_v3` 源稿重放配方与词表（保证 final 可由源稿完整重建），
故重复执行时**命中数照旧 >0 但产出字节完全相同**。回执以 `content_changed` / `is_rebuild_only`
区分「源稿重建」与「实际变更」，显示为「（源稿重建，final 无变化）」，避免作者误判。

**收录标准**（作者维护时遵循）：

- ✅ **硬强度副词删除**：瞬间／狠狠／死死／疯狂／剧烈／彻底 是 AI 腔指纹，正确解法是**删除**；
- ✅ **轮换用于高频但正当的词**：神色／目光 这类无法删除、又容易被模型反复使用的词，
  用 `rotate` 分散成多种表达；
- ❌ **软程度副词不收（重要边界）**：缓缓／轻轻／微微／淡淡／静静／悄悄／默默／渐渐
  **刻意不进词表**，交回技能卡的**配额制**（每词 ≤5／章）管理。
  **判据：删掉后是否只剩动作骨架？是 ➔ 不该进引擎词表。**
  实测反例：把「缓缓」清零后，「双眸缓缓阖上」变成「双眸阖上」——动作对，但**失去节奏与分量**，
  正是「干巴」的成因。词表能防滥用，但一刀切删除会伤及正常行文；
- ❌ 不做「以喻换喻」（刹那间→转眼间）——把套话换成另一个套话没有意义，应直接在技能卡禁掉；
- ❌ **轮换不是万能**：它只能把 A 的重复再分配给 B。若原稿本就偏爱某候选（如「眼神」），
  轮换后它依然高频——真正的根治靠技能卡里的**用词配额**（T 表 / F 表）；
- ❓ 需看语境的（冷笑／宛如／意味深长）**不进词表**，交给 Auditor 逐章配方。

**已知局限（诚实记录）**：

- 词表只处理**无条件确定**的用词问题，**不能替代**逐章语义判断。删除类规则尤其危险：
  它无法分辨"这个副词在这里是否承载语义"（如「胸口起伏剧烈」删「剧烈」后程度丢失）；
- **词表只做减法，无法解决「干巴」**：删掉 AI 腔之后，稿子可能只剩骨架。防干巴靠的是
  **Drafter 的具体化下限**、**Tuner 的「抽象→具体」等量替换**、**Auditor 的干巴检测**——
  这三条是卡片职责，不是引擎职责（引擎不做文学判断，不变量 8）；
- 词表**不改动 `raw/` 与 `log/audit/`**——那是匹配源，清理会破坏重建链；
- 配方与词表会**叠加**：若 Auditor 配方已改写过某句，词表在其结果上继续生效。
  两者责任需分别核对（本项目 ch_005「睫毛剧烈颤抖了几下」丢「了几下、终于」经查是配方所致，非词表）。

## 设计不变量（改动前必读）

1. **SSOT**：状态只从细纲（beats front-matter）流入台账，正文绝不反向提数；
2. **四层数据完整性模型**：事务预检（`apply_state_deltas` 先校验全部冲突，任一冲突=零写盘）→ 按章幂等增量（重放安全）→ 原子写盘（tempfile+os.replace）→ 损坏硬失败（隔离 `*.corrupt-*` 并抛 RuntimeError，退出码 4）；
3. **sync 幂等**：同一章重复 sync 不得虚增任何计数（co_occurrence.total_co_occurrences、entity_timeline.events、arc_history、relations.history 均按 chapter 去重，判定依据 `state/sync_log.json` 指纹）；同章同稿重放跳过 ♻️；细纲量化数据变更须 `--force` 重同步；纯文笔修订用 `--refresh` 仅刷新字数；
4. **宽容自愈边界**：非核心字段缺省静默兜底，但 **JSON 损坏、死亡角色登场、充能透支、空正文封存、SSOT 覆盖、init 覆盖已有书籍** 六类必须硬阻断；
5. **探针强弱分级**：纯物理事实与数据探针（认知盲区、称谓矩阵、物象落地 + 字数计量），绝不越权检测文学文风与排版节奏；阻断级仅 2（空正文/确认级认知泄露），其余一律 warning 交由 Auditor 审阅；
6. **配置唯一真值源**：新旋钮必须进 `config.py DEFAULT_CONFIG` + `CONFIG_GUIDE`，禁止在业务模块硬编码；
7. **版本一致性**：`engine/__init__.__version__` 是唯一版本号，cli/cockpit 均动态引用；
8. **引擎不做文学判断（FIND-CT70 · 作者裁定）**：字数区间、对白占比、章型连排"疲劳"等一切审美/体裁裁量**不得**进入引擎判定；引擎只输出事实计量（字数、序列、计数），评价与调整 100% 归 Stage 1/2/3A/4A 的 LLM。新增任何"达标线/黄牌/占比阈值"类判据都视为违约；
9. **两级定级 + 自愈留痕（FIND-CT71/72/73 · 公理二落地）**：
   - **error（阻断）只保留会让剧情讲不通或让下游崩栈的真矛盾**：生死状态自相矛盾、已故角色无豁免登场、细纲文件不存在、状态表损坏/蒸发、充能透支、空正文、SSOT/init 覆盖；
   - **其余一律 warning（提醒）**：选填字段缺漏、ID 笔误、引用悬空、撞号、账面瑕疵、统计口径受扰；
   - **能确定性推断的由引擎自己修**（`state.py` 自愈层），修完必须写进 sync 报告 `healed` 清单公示；推断值一律标注来源（如 `planted_ch_source: inferred`），**绝不猜剧情**（叙事因果交作者/Stage 4C）；
   - **假自愈是比漏报更严重的缺陷**：干净数据重放必须零自愈动作（回归靶点 C-27），同类提醒 ≥3 条要折叠成一行（C 段 + FIND-CT74），避免无人值守日志刷屏。
